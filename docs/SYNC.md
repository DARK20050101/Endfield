# 拉取、导入与跨设备同步

三个入口共享规范化、身份映射和合并规则：游戏 API 拉取、历史文件导入、可选 WebDAV。输入凭据和历史数据不可混用。数据库结构见 [DATABASE](DATABASE.md)。

## 游戏拉取

SyncEngine 接收已验证 CredentialContext 及角色/数据流。角色按池类型或已验证范围分页，武器先列池再逐池分页。检查点至少按角色、record_type、stream_key 隔离；未经证明不可跨池共享最大 seqId。

1. 装载角色、已完成水位及未完成任务状态；对相同角色/流只允许一个写入任务。
2. 从已验证的最新页或安全恢复点请求，运行时验证响应结构和身份。
3. 规范化记录、去重；每页数据与 resume_cursor 在同一数据库事务提交。
4. 同步过程中跟踪已访问游标、页面摘要、页数上限；重复 cursor、空页却 hasMore、游标不前进都应停止并记部分失败。
5. 只有排序/完整性已确认且不存在未完成缺口时，遇到已知记录才允许提前停止。首条重复不意味着所有剩余历史已完整。
6. 全数据流完成后才更新 completed_watermark / last_success_at。部分失败仅保留恢复点和已写记录，不能把新最大 ID 当作完整水位。
7. 汇总角色与武器状态；任一池失败则显示部分成功与可重试范围，不覆盖历史。

重启或重新授权后，恢复策略同时考虑最新新增记录与旧任务缺口；游标失效时从最新页重放并幂等合并，不只跳到旧页导致漏掉新增数据。具体 cursor 语义在 [API_RESEARCH](API_RESEARCH.md) VERIFIED 后确定。

Full Sync 是拉取接口当前可见范围并合并，不是清空重建；不能声称接口窗口等于全部历史。Incremental 和 Full 使用同一去重与保留规则。

## 错误与取消

超时、离线、服务端临时故障可有界退避加抖动；限流尊重服务端可验证的 Retry-After，并限制并发。授权过期不能当网络故障无限重试；协议变化隔离样本、停止写入受影响页。请求和任务都可取消，取消不能标记成功。

进程中断时事务要么整体提交、要么不提交；重放不会重复计数。日志只保存错误类别/脱敏任务信息，不保存请求 URL、Token 或原始响应。

## 历史导入

目标 Importer：bhaoo、RoLingG、EndCat 格式、Generic JSON、CSV、XLSX。支持格式仍需样本与许可审查；理解格式不等于复制对应工具的源码。V0.6 完整实现，Phase 0 只定义边界。

选择文件 → 大小/结构校验 → 格式检测 → 账号/角色映射 → 预览新增/重复/冲突/未知数 → 用户确认 → 事务写入 Unified GachaRecord。

不信任文件声明的角色或 channel；缺可靠身份时待归属暂存。缺稳定 record ID 时不能仅凭时间和物品去重；保留来源及歧义等待解决。解析器必须保留未知字段含义，不把 is_free 缺失解释成付费抽。

重复导入同一有效文件不增加记录数；导入后 API 同步也应识别相同抽取。候选数据携带游戏凭据时拒绝或剥离，不成为 ImportedCredentialSource 的自动输入。

## WebDAV 契约（V0.5）

默认关闭；用户主动配置自己的同步服务后才启用。Android/Windows 各自取得游戏授权，同步业务数据不代替登录。仅一台设备也可完整使用应用。

快照 envelope：schemaVersion、deviceId（仅该同步空间的随机标识）、generatedAt、dataVersion、accounts、roles、records、metadata、显式允许的 settings。GameAccount/GameRole 只同步归属所需字段；其中 UID/历史不是匿名数据，配置界面需清楚说明上传内容。

不包含密码、Cookie、OAuth/U8/refresh Token、任何 game credential、完整 URL、credential_refs、安全存储文件、WebDAV 密码、设备路径、诊断日志或本地拉取游标。raw_json 默认不出设备；通过字段白名单导出规范化记录。

## 合并与并发

- 外部身份元组映射双方内部 UUID；不能用本机 UUID 直接判断两个设备的角色是否相同。
- 记录按经验证的稳定复合键做集合合并；同键不同 payload 保留冲突，不能 last-write-wins。
- remote newer / local newer / both changed 都比较基线版本与内容，不能只看 generatedAt 或设备时钟。
- 元数据按来源/版本/有效期校验，不盲信较新的未知规则；设置仅同步允许的偏好，冲突按字段明确规则或用户选择。
- V0.5 不传播历史删除；本地删除不隐式擦除另一设备记录。未来需要删除同步时再设计 tombstone 和恢复窗口。
- 下载先验证 schema、体积、身份、记录及 checksum；损坏或未来版本数据不应用，保留本地库与上次可用快照。
- 上传先生成完整的版本化不可变数据文件，校验上传成功后再条件更新 manifest。使用 ETag / If-Match 等并发机制；冲突则重新读取合并并有界重试。
- WebDAV 服务器不支持可靠的条件写或原子发布时，不能假设安全多端写；降级只读/受控单写并显示限制。MOVE 等能力亦需实测。
- 中断上传留下的孤立版本不得被 manifest 引用；读者只应用完整已发布版本。校验和只验证完整性，不代表端到端加密或可信来源。

## 验收场景

重复页/重复导入、多池相同 seqId、多角色相同 UID 表象、同秒同物品、半程失败后恢复、Token 过期、游标循环、取消、离线、数据库提交失败、两设备同时新增、远端损坏/未来 schema/中断发布、同键异内容冲突、快照无游戏授权。
